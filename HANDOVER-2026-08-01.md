## 2. What changed, by behaviour

### The app is operational when it opens

`electron/main.mjs` gained `openBoundBrowsers()`, which opens the Chrome belonging to every account
bound to this machine, after `win.loadURL` and deliberately not awaited. It goes through the
console's own `/api/account/open` rather than importing the launcher, so there is one code path that
opens a browser and one place that decides whether it is allowed. It does not retry. Opt out with
`REDBOT_NO_AUTO_BROWSER=1`; the Electron smoke test sets it.

Those windows open **off-screen** (`--window-position=-32000,-32000`) plus
`--disable-backgrounding-occluded-windows` and `--disable-renderer-backgrounding`, because Chrome
throttles a window it believes is not visible and an off-screen page would otherwise load slowly or
not at all.

**They are headed, and must stay headed.** Headless was asked for and refused: Reddit answers a
headless browser with a block page served as HTTP 200, so reads come back empty and actions fail
silently while looking fine. `src/browser.ts` already throws `HeadlessBrowserError`, `doctor` calls
it a FAIL, and `TIER0-BLOCKER-2026-07-27.md` records both send attempts hitting it.

Because an off-screen window cannot be reached by clicking, alt-tabbing, or launching Chrome again
(a second launch only messages the running instance), `showBrowserWindow()` in `src/browser.ts` and
`POST /api/account/show` bring one back: read a page target from the debugger's own `/json/list`
(Playwright does not expose a targetId), `Browser.getWindowForTarget` for the windowId, then
`Browser.setWindowBounds` — `windowState:'normal'` **first and alone**, because a minimised or
fullscreen window rejects a combined change. The Accounts screen shows **Show browser** while a
browser is running.

### A signed-in Chrome is now a BLOCKING requirement

`src/requirements.ts` moved `browser` from advisory to blocking. The old rationale — transient, so
blocking would lock a person out every morning — rested on nothing but a person opening the browser,
and boot now does. The original argument is kept verbatim in the header rather than deleted.

`headed` stays advisory: it is a property of a browser already attached, and `doctor` already fails
on a headless attach.

### A taken debug port moves itself

`launchChrome` no longer refuses when the port is `foreign`. It reallocates through
`changeAccountPort({auto:true})` — the same allocator the "pick one for me" button uses — and
reports `movedFrom`. This is **not** attaching to the squatter, which is the defect the check exists
for: Chrome handed an occupied `--remote-debugging-port` starts anyway and silently yields the port.
Moving to a free one guarantees the browser redbot opens is the browser redbot attaches to.

### An account can use a Chrome profile that is already signed in

`profileDir` may now be an **absolute path**, and the folder is used where it is. Nothing is copied:
a Chrome cookie and login store is DPAPI-bound to one Windows user, so a copy is at best pointless
and at worst looks populated and cannot authenticate.

`join()` cannot express this — `join('C:\app','D:\real')` yields a path that exists nowhere — so
**`resolveProfileDir()` replaces it at six sites**: `profileState`, `ensureProfileDirs`, the two in
`ports.ts` that decide `profileOnDisk` and which browser owns a port, and the two in the console
that report existence and hand `--user-data-dir` to Chrome. Missing any one reports an adopted
profile as missing, or checks a different browser than the one that was opened.

`adoptProfileDir()` (`src/console-accounts.ts`) refuses a running browser, a folder with no Chrome
markers, and a folder another account uses. `POST /api/account/use-profile`.

### The console stopped interrupting

- The walkthrough no longer opens itself. Its flag is per-install, so every reinstall met a
  full-screen overlay. `?` and the `?` key still open it. `redbot.seenGuide` is still **written**,
  because the UI suite pre-sets it to stop the overlay eating clicks.
- **Setup is now Settings**, behind a gear on the right, and is no longer a tab. It is removed from
  the `R` screen map — leaving it there would hide `#v-setup` on every navigation, including while
  the panel is open. `setup()`'s four self-redraws became `setupAgain()`, which is **silent when the
  panel is closed** because two of those callers are background dependency scans.
- Settings auto-opens only for **durable** blockers. A closed browser is transient and boot already
  opens one, so it no longer takes the screen on a routine launch.
- The banner no longer says "Setup is not finished" for a closed browser — that is a claim about the
  install, and it sent people to a screen containing nothing that opens a browser.
- The Today checklist is startable: each step redbot can begin is a button that lands on the screen
  that does the work and pre-selects the account. **"Check your first comments in a signed-out
  window" deliberately stays text** — it needs a browser redbot does not drive, and a test pins it
  as a `DIV`.

### Updating

- An **update button** in the top bar. It *checks*; the bar it reveals *installs*. Both calls pass
  `force`, which spends a live request and bypasses the per-version dismissal — before this, hiding
  the notice for a version was permanent for that version.
- **`apply()` refuses while redbot is busy.** `quitAndInstall` kills this process and every child:
  the console server and whatever CLI it spawned. `ACTIONS.__reply` is `stoppable:false` because
  dying between submit and confirm leaves a live comment on Reddit that redbot does not know it
  made. `createUpdater` takes `isBusy`; `main.mjs` answers it from `/api/pulse`. The check sits
  immediately before `quitAndInstall`, not at the top of `apply()` — downloading during a run is
  harmless, and a check at the top would be about a state that had a 100 MB download to change in.
  It **fails open**: everything that could be mid-flight is a child of the console server, so a
  console that cannot answer is running nothing.
- redbot has never auto-updated and still does not. `autoDownload` and `autoInstallOnAppQuit` are
  both explicitly `false`.

### Packaging

- The app wears **redbot's own mark**. `electron/make-icon.mjs` reads the favicon data URI out of
  `tools/product/index.html`, decodes it, and rasterises it with the Playwright already in the tree.
  The PNG is committed; a packaging step that needs a browser to make an icon fails on a machine
  without one. The header's inline `<svg>` is deliberately not the source — it paints with
  `var(--ember)`, which resolves to nothing outside the console stylesheet.
- **`npm run build` now clears `dist/` first.** See §4 — this one bit us.

## 3. Tests

Run **serially**. `npm test` as scripted runs files concurrently and several write the same SQLite
test DB, which produces 20–35 `DbBusyError` failures that move run to run. That is why
`AUDIT-2026-07-31.md` labels its number "serial".

```
node --env-file=db/sqlite/.env.test db/sqlite/reset-test-db.mjs
node --env-file=db/sqlite/.env.test --test --test-concurrency=1 \
  "dist/test/*.test.js" "db/sqlite/schema.test.mjs" \
  "tools/operator/server.test.mjs" "tools/product/server.test.mjs" "electron/updater.test.mjs"
```

| Suite | Result |
|---|---|
| Engine + console + updater (serial) | **798 tests · 794 pass · 4 fail** |
| UI (`npm run test:ui`) | **79 / 79** |
| Typecheck / build | clean |

The 4 failures are pre-existing and were each reproduced with the changes stashed:

- 3 × `redbot tokens mint` — need a dashboard service that does not exist yet
- 1 × `/api/state sends one page of review…` — `ECONNRESET` on the heaviest request, a flake

**A fifth thing worth fixing:** the `npm test` script itself should pass `--test-concurrency=1`, or
the tests should stop sharing one DB file. Right now the published test number is not reproducible
by the published command.

## 4. Traps found the hard way

**Stale `dist/` ships.** `tsc` does not delete a `.js` whose `.ts` is gone, so switching off
`tier0/port-to-desktop` stranded `dist/test/composer.test.js` and `headless-refusal.test.js`. A full
run reported 9 failures where there are 4 — five of them from files not in the source tree. The test
noise is the mild half: **`dist/**/*` is the first entry in the `files` allow-list in
`electron-builder.yml`**, so a stale `dist` ships dead modules from another branch inside the
installer. `npm run build` now runs `npm run clean` first. `AUDIT-2026-07-31.md` hit the same thing
and removed the files by hand, which is why it came back.

**Build releases on one machine.** Every boot of the released 1.0.6 logged
`migrations failed: Applied migrations have changed on disk` while `/api/setup` reported the database
green and `migrate.mjs verify` was clean — a failing startup check invisible in the UI. It
disappeared on 1.0.7, which was built on the machine whose database first applied those migrations.
Git shows zero content diff in `db/sqlite/migrations` between the two, and git itself warns
`LF will be replaced by CRLF` in this repo. Build elsewhere and the checksum check complains again.

**Release asset names.** `latest.yml` names `redbot-Setup-1.0.7.exe` (hyphens); electron-builder
writes `redbot Setup 1.0.7.exe` (spaces) to disk. Upload under the disk name and the updater 404s.

**A draft release is invisible to the updater** — absent from both the Atom feed and
`/releases/latest` — so the app reports "no published versions" while the release looks published.
`releaseType: release` is set in `electron-builder.yml` for this reason.

## 5. Open, and not ours to close silently

1. **`tier0/port-to-desktop` is unmerged and unreleased.** Decide: cherry-pick or delete.
2. **Three features do not exist** and were scoped but not built: subreddit *discovery* (`search`
   finds threads, not subreddits), **bulk commenting** (only the one-at-a-time `auto` loop), and
   **creating a post** — `src/reddit/post.ts:2`, *"Publishing a comment. The only write path in
   redbot."* The last is a publishing-safety surface and needs a human decision before it ships.
3. **Nothing has ever been published to Reddit.** `AUDIT-2026-07-31.md`, measured against the
   checkout's own corpus: 80 threads, 14 drafts, 19 certifications — **all REJECT, zero CERTIFIED,
   0 replies sent**. Every claim about contribution quality remains theoretical —
   `docs/05-RISK-REGISTER.md` R-01. Note the installed app writes to `%APPDATA%\redbot\data`, a
   separate and empty store, so a fresh install reports zeroes for a different reason.
4. **Scan-threads and comment are unproven on this branch.** The code paths exist; proving them
   needs a Chrome signed in to Reddit, and the workstation's profiles were empty until the
   adopt-profile control landed.
5. **`npm test` is not reproducible** — see §3.
