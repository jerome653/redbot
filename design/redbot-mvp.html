redbot

Finds the Reddit conversations worth your time, drafts a reply, and posts only what you approve. Anyone on the team can run it — support, marketing, sales, engineering. It is not an engineering tool.

What it does

  1. You open Reddit in a browser and sign in — once.
  2. redbot reads a subreddit and collects the threads.
  3. redbot scores each one: could SGEN genuinely help here?
  4. redbot drafts a reply to the best ones.
  5. You read it, edit it, approve or reject.
  6. redbot posts what you approved and records what happened.

Step 5 is the point. Nothing reaches Reddit without a person saying yes.

Where it actually stands

Validated by adversarial testing, not by assertion. Nine defects have been found by trying to break it — three of them critical. Eight are fixed outright with regression tests. One was reduced to a known, bounded residue, described below rather than hidden.

Two were found after the first certification pass, by attempting a real publish. Both were silent-failure bugs, which is the class this project keeps producing.

Nothing here is broken code. What remains is one measurement that needs a bigger sample and one decision deliberately reserved for a person.

Why “publish” is not green Not a bug, and not a missing feature. redbot will not post without a human keystroke, and nobody has pressed the key yet. That is the design working. An automated approval was attempted during testing and was correctly refused — if a script can approve, the approval step is decoration. It turns green the moment someone reads a draft and says yes.

Is the writing the problem? No.

Worth stating plainly, because “ranking unstable” reads like the replies were bad. These are two different steps, and only one ever wobbled.

StepModelJobState
TriageHaikuscore 15 threads 0–100, cheaplywas inconsistent — largely fixed
DraftingSonnetwrite one reply properlynever the problem

The wobble was in triage: the prompt said “score 0–100” and left the model to invent a number, so the same thread came back 95, then 85, then 20. The fix was not a better model — it was removing the free choice. Scoring now runs through fixed gates (is it a question → is it in scope → how specific is it), each landing on a set value.

The honest residue. Across three runs of six threads, three scored identically every time and five landed within ten points. Two borderline threads still flip between “worth answering” and “not worth answering” — both sitting near the cut-off, where a small score change crosses the line. The practical cost is that a marginal thread may or may not appear in the queue on a given run. It does not affect what gets written, and a person still chooses from the queue.

From an actual draft, unedited, on a live thread about database load: “…WP Super Cache does not cache URLs with a query string unless you explicitly allow it. If your newsletter links carry tracking parameters, every recipient who clicks lands on an uncached page at the same time — the same load pattern as having no cache at all.”

Specific, checkable, non-obvious. The writing was never the risk. The risk was which thread it picks, and that is the part that got fixed.

DEFECT-08 — the approval gate failed open

The prompt helper resolved any unrecognised answer to the first option. The publish gate offers a / e / r — approve, edit, reject — so the fallback for a blank line, a typo, or a stray newline was approve, and post. A gate whose default is “yes” is not a gate.

It had never fired because the one non-interactive run to date died at end-of-input before deciding. A single stray newline would have published. The safe answer is now a required argument that the caller must name explicitly — reject for publishing — unrecognised input re-asks instead of guessing, and a non-interactive stdin refuses outright rather than proceeding. Four regression tests pin it, including one that reads the call site to catch anyone re-introducing a positional default.

DEFECT-09 — the failure that reported nothing

Drafting stopped working and said only claude CLI exited 1: — with nothing after the colon. A batch run produced no drafts for forty minutes with no usable explanation.

The real cause was correct behaviour: per-operator authentication refused to borrow the machine’s ambient Claude login, exactly as intended. But the “not signed in” check sat after the exit-code branch, so a non-zero exit skipped it — and the CLI writes “Not logged in” to stdout, while the error path only read stderr. The check now runs first and reads both streams, and any other non-zero exit reports whichever stream actually spoke rather than an empty string. The message now names the operator and prints the exact sign-in command.

The two critical defects from the first pass

DEFECT-01 — live session cookies were committable to git. redbot sits inside a git repo and was entirely untracked: 4.6 GB of Chrome profile including Login Data and working Reddit session cookies for two accounts. One git add -A would have committed them. This is the same failure class flagged in the Appilot teardown, and it appeared in our own repo within a day. Fixed, with a regression test.

DEFECT-06 — agent text leaked into drafts. Early drafts contained plan-mode notes, internal tool names, and a local Windows path — text that would have been posted publicly. Root cause: the CLI ran as a full coding agent inside the project and inherited a plan default mode. Fixed three ways, and the linter now blocks 31 of 31 adversarial leakage cases with zero false positives.

That linter earned its place on re-check. One draft written before the rule existed opened with “Draft below, WP Super Cache diagnosis angle, ready to edit/post” — text addressed to the operator, not to Reddit. Re-running the current linter across every stored draft blocked that one and passed the rest. It is now marked rejected and cannot be posted.

The finding that made it work

Every attempt where the software launched a browser was blocked by Reddit — Chromium and real Chrome, headless and headed, plus old.reddit.com at HTTP 403. The block even arrives as HTTP 200 with a block page in the body, so a naive status check would have called it success.

Attaching to a Chrome window you opened works.

node dist/cli.js read wordpress

  Found 25 post links.
    [1/25] [Guide] Complete cleanup and securing of WordPress after REST Batch AP…
    [2/25] How do you keep track of a handful of WordPress client sites?
    …
  OK  Collected 25 threads (25 new).

One architectural rule — attach, never launch — turned zero threads into twenty-five. It is also the better design: the session is genuinely yours, no password ever reaches redbot, and there is no session file to leak.

The accounts, and the real bottleneck

Two accounts exist and were verified signed in on 2026-07-22: docs-architect and jrum_sgen. Both sit at 1 karma — measured on the live profiles, not assumed. Neither has posted anything.

This is the constraint that actually governs the next six weeks, and it is not a software problem. A 1-karma account has precisely the profile Reddit’s filters are built to catch. Early comments get removed, collapsed, or held for a moderator — often silently, still visible to you while signed in and invisible to everyone else. Checking your own profile does not detect this; a signed-out window does.

Warming plan

StageTargetWhat it looks like
1 · weeks 1–250–100 karma each 2–4 comments a day maximum, threads under two hours old, zero links and zero product names. Comment in a few subreddits outside the work topic — an account whose entire history is WordPress support reads as a marketing asset. Verify the first ten comments signed out.
2 · weeks 3–6300–500 karma each Narrow to two or three subreddits and appear regularly. Prioritise questions with few existing answers — a good reply to an unanswered question earns far more than the tenth reply to a popular one. Stay in the thread and answer follow-ups.
3 · week 7 onnormal operation The accounts clear most automatic filters and redbot’s ordinary loop applies. Still no unprompted promotion; four comments a day from an established account is plenty.
Rules that never relax The two accounts never touch — not the same thread, no replies to each other, no votes on each other. That is the single behaviour that turns two accounts into vote manipulation, and Reddit bans across the whole network for it. There is no voting at all; redbot has no code path for it. And if an account is suspended, stop — a replacement from the same machine is ban evasion, and turns one suspension into a permanent one.

How many accounts can this run? Technically the ceiling is memory — each account is a Chrome profile on its own port at roughly 300–400 MB, so eight to twelve on a normal workstation. The real limit is much lower: two active accounts, because Reddit treats several accounts posting from one network about one subject as a single operator, which is what they are. A third is only worth creating once the first two plainly behave like separate people.

redbot helps with finding threads, drafting, pacing under the rate limit, refusing anything promotional, and logging removals so silent ones become visible. It does not shorten the waiting. Karma comes from other people finding the comments useful, and no automation changes that. Full plan: ACCOUNT-WARMING.md.

Why there are no phones in this

Appilot runs on real Android devices because mobile-device automation is the product they sell. SGEN wants replies on Reddit.

The fact that settles it Reddit does not treat a comment differently depending on where it was written. App or browser — same account, same service, same visibility, same ranking. There is no engagement, reach or trust benefit to posting from a phone.

Android buys exactly one thing: device-fingerprint diversity, which only matters if you are concealing a connection between accounts. redbot's accounts are disclosed SGEN staff — the connection is public on purpose.

The cost difference compounds with every account. In Appilot's model an account is a phone, a SIM, a proxy and a shelf slot. Here it is a folder on disk.

redbot runs one Chrome profile per account. That separates cookies, session tokens, storage, cache and history — which is the layer Reddit’s own session tracking reads. Two accounts on one machine look like two browsers on one household connection, which is what two colleagues in an office look like.

The fingerprint point is backwards from the folklore A fingerprint links two accounts only when it is rare. Two standard Chrome-on-Windows profiles are not linked by it — that is the most common configuration on earth. Randomising canvas noise makes each profile unique and inconsistent between page loads, which is itself a detectable spoofing signature. redbot stays ordinary on purpose.

And the framing that makes most of it moot: every proxy and anti-detect technique exists to make connected accounts look unconnected. redbot’s accounts are disclosed SGEN people — the connection is public by construction. The question is not whether Reddit notices they are related. Colleagues are related. The question is whether the behaviour looks like manipulation, and that is answered by conduct, not infrastructure.

Signing in — once per account, silent after that

The goal is that nobody thinks about authentication day to day. That is achievable, and here is exactly how far it goes.

MomentWho does whatHow often
First set-up of an accounta person signs in, in a real browser windowonce, ~60 seconds
Every run after thatnothing — redbot reuses the stored sessionalways silent
Keeping it aliveredbot loads Reddit in that profile on a schedule so the session does not age outautomatic
Moving to another machine or personexport the encrypted session, import it theresilent — the second person never signs in
Session finally expiresredbot flags which account needs attention, before a run failsrare

So the honest shape is: one sign-in per account, ever — not per user, not per device, not per session. A second operator on a second machine imports the session and never sees a login form. That is as close to silent as this can get without storing passwords.

What redbot will not do, and why It will not store your password and replay it into the login form. That is a permanent liability rather than an expiring one, it breaks the moment two-factor is switched on, and it is the precise mistake that made the Appilot APK a problem — two live keys sitting inside a zip file on disk. A session can be revoked from Reddit’s own settings without redbot knowing; a stored password cannot.

What is stored, concretely

  • A per-account Chrome profile directory — cookies, session tokens, storage, history.
  • An encrypted export of that session when you move it between machines.
  • Never a password. Never a recovery email. Never a 2FA secret.

Status: the persistent session and the sign-in check are working — proven today. Encrypted export/import and the keep-alive schedule are specified, not yet built.

Credentials — what redbot stores, and what it never stores

redbot never stores a password. You sign in once per account in a real browser window. What persists is the session, inside that account’s own Chrome profile. Moving an account to a second machine is an export and import of that encrypted session file, not a credential hand-off.

This matters because a stored password is a permanent liability, while a session expires on its own and can be revoked from Reddit’s own settings without touching redbot. It is also why the Appilot APK shipping two live API keys inside a zip file was such a bad sign.

What it refuses to do

These are enforced in code, not politely requested of the model. A draft that breaks one cannot be posted even if you approve it.

  • If a reply mentions SGEN, it must say you work there.
  • No invented war stories — it will not write “I hit this exact problem last year”.
  • No fake typos or forced casualness to seem human.
  • No “hope this helps!” filler.
  • No threads that can only be answered with a sales pitch — r/WordPress rule 1 is “No promotions of products or services”.

There is no voting. redbot cannot upvote or downvote anything.

The scoring, judged on its own output

From the live run, the four it turned down without being asked:

A cleanup guide — “solved content being shared, not help being requested”.
A client-workflow thread — “already answered in-thread”.
The community FAQ megathread — “a reference resource, not a problem to solve”.
A plugin author’s own tool — “not a help request”.

Refusing well is most of the value. Fifteen of twenty-five were filtered out before anyone spent time on them.

Claude sign-in is per operator — redbot never borrows whichever account happens to be signed in on the machine. That rule is currently what stops it running unattended, which is the correct behaviour.
