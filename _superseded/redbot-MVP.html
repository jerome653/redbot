redbot — MVP Proposal

For approval · 2026-07-22 · prepared for SGEN
Supersedes: nothing. Depends on: REDBOT-CANON.md, ADR/, Requirements/
Companion: Projects/appilot-analysis/ — the teardown this is answering

The ask, in one paragraph

Build redbot: a Reddit user agent that does what a person does — reads, searches,
browses, writes, replies, manages its own account — under SGEN's direction, at human pace,
from real accounts. Same capability as the Appilot bot SGEN already paid for, built on
SGEN's existing stack instead of a phone farm, with the six structural problems found in
Appilot's binary fixed by construction rather than inherited.

~8 weeks to a tested system. ~$20–40k build. ~$2–4k/year to run.
Against Appilot's shape: 5–6 months, ~$100k, $30–45k/year.

The difference is not cleverness. It is that Appilot built for their business — selling
mobile-device automation to many customers — and SGEN does not need mobile. SGEN needs the
capability.

2. What the MVP does

In scope

Agent

  • One account, real browser session, saved and restored — no re-login every run
  • Read: open subreddit, open post, read comment trees, scroll, search
  • Write: comment on a post, reply to a comment — both behind the approval gate
  • Account health: is the session alive, is it shadowbanned, what is the karma
  • Recover from a wrong screen without ending the run
  • Kill switch: one command halts everything, mid-step

Intelligence

  • Engagement scoring → tier 1/2/3 (is this thread actually alive right now)
  • LLM qualification → is this answerable, is it in SGEN's competence, is it answerable

without pitching the product

  • LLM drafting → a reply a real engineer would be willing to put their name on
  • Draft linter → rejects missing disclosure, fabricated experience, deliberate typos,

engagement bait

Control

  • Approval queue: read the thread, read the draft, edit it, approve or reject
  • Audit log: every write, before and after, with content and permalink
  • CLI: run, serve, approve, halt, doctor

Engineering

  • Workflows are JSON documents — new behaviour without a release
  • Selector pack v1, tiered resolution, degradation telemetry
  • Rate ledger enforced in code — no path from a write to the network skips it
  • Log-normal timing, not uniform ranges
  • Offline test suite that passes with the network disabled

Out of MVP — specified, phased

Original posts · edit/delete · direct messages · join/leave/save/follow/hide/report ·
multi-account orchestration · vote actions (ADR-0007) · mention monitoring *(moves in if
the primary objective is defensive)* · MOE integration · any platform but Reddit.

The layering is the point. Surface knows the DOM and nothing about Reddit. Actions know
Reddit and nothing about workflows. Engine knows intent and never touches the DOM. Control
knows people. A CI test fails the build if an import points the wrong way.

That rule exists for one reason: Appilot's RedditAutomation class holds 608 of its ~1,500
methods because perception, actuation, flow control, data capture and recovery all live
together with no boundary. That collapse is not an accident of skill — it is what happens
without an enforced line. redbot draws the line on day one and lets CI hold it.

4. Multiple accounts — how, and where the ceiling is

This was asked directly, so here is the real answer rather than a comfortable one.

The mechanics are easy

Playwright's isolation primitive is the browser context. One browser, N contexts, each
with its own cookie jar, localStorage, sessionStorage and cache. Verified against current
Playwright docs:

// log in once, by hand, per account — then never again
await ctx.storageState({ path: 'data/accounts/sgen_dev/session.json' });

// every run after that restores the session
const ctx = await browser.newContext({
  storageState: 'data/accounts/sgen_dev/session.json',
  proxy:      { server: 'http://…', username: '…', password: '…' },  // per context
  locale:     'en-GB',
  timezoneId: 'Europe/London',
  viewport:   { width: 1440, height: 900 }
});

proxy, locale, timezoneId, viewport, geolocation, colorScheme and permissions
are all settable per context. For a heavier profile — one that keeps extensions and full
browser state on disk — chromium.launchPersistentContext(userDataDir, opts) gives each
account a real Chrome profile directory. *(Caveat from Playwright's own docs: use a fresh
directory, never Chrome's main "User Data" folder, and no two instances may share one.)*

The ceiling is where it gets honest

Contexts isolate storage. They do not isolate identity.

SignalIsolated by a context?
Cookies, localStorage, session✅ yes
IP address❌ no — same machine, same IP, unless you set a per-context proxy
User agent, locale, timezone, viewport⚠️ settable, but you have to set them
Canvas / WebGL / font / audio fingerprint❌ no — same browser binary, same hardware, identical across every context
Behaviour: timing, phrasing, active hours, subreddit overlap❌ no — that is a design problem, not an API one

Reddit states it correlates IP address, login patterns and voting timing to identify
coordinated accounts. Contexts do not defeat that, and nothing in a browser automation
library does.

This is precisely why Appilot used one physical phone per account. A separate phone on
a separate SIM genuinely is a different device on a different network. That is the one thing
their architecture buys that redbot's does not, and it deserves to be said plainly rather
than buried.

What redbot does about it

Ordered by how much they actually help:

  1. One context per account, always. Never share a session. Baseline, non-negotiable.
  2. Never run two accounts at the same time. Serial execution, staggered by hours. Timing

correlation is the cheapest signal to give away and the easiest to avoid.

  1. Per-account persona in config — its own subreddits, its own active hours, its own

writing register, its own rate ceiling. Accounts that behave identically look identical.

  1. Per-context emulation — distinct UA, locale, timezone, viewport per account.
  2. Persistent profiles (launchPersistentContext) once accounts have history worth

keeping.

  1. Per-context proxy — optional, and cheaper than the category assumes. See §4.4.
  2. Beyond ~5 accounts: separate machines or VMs, or a purpose-built anti-detect browser.

Notably, the anti-detect vendors Appilot's own site lists — Multilogin, GoLogin, AdsPower,
Kameleo — exist because this ceiling is real and browser contexts do not clear it.

4.4 What multi-account actually costs

An earlier draft of this proposal priced proxies at $30–80 per account per month. **That was
wrong by roughly 10–100×* — it quoted dedicated 4G mobile ports*, which is phone-farm
equipment, not the product a browser needs. Corrected, with pricing verified 2026-07-22:

ProductReal priceRight for redbot?
Static residential IP, dedicated, flat monthly$0.30–$6 per IP/month (Webshare from $0.30; Oxylabs $16 premium tier)yes, if you want IP separation
Rotating residential, metered$1–8/GB, $3–8 typicalworks, but rotation buys nothing here
Mobile / 4G port$30–80/monthno — that is for imitating a phone

Three accounts on dedicated static residential IPs: $11–216/year.

And the more useful correction: you may need none of it. Reddit does not action accounts
merely for sharing an IP — it cannot, since households, offices, universities and carrier-grade
NAT put large numbers of genuine accounts behind single addresses. Enforcement follows
coordinated behaviour: accounts voting on the same content, replying to one another, posting
the same links, moving in lockstep.

The entire proxy and anti-detect industry exists to make **connected accounts look
unconnected**. redbot's accounts are disclosed SGEN staff. The connection is public by
construction. There is nothing to conceal, so there is nothing to buy.

Shared IP is fine provided the accounts never interact, never post in the same thread, keep
different active hours and different subreddits, and do not vote. Every one of those is a
scheduling rule enforced by the engine — not a purchase.

Revised cost of multi-account:

Cost
Infrastructure for 2–3 disclosed accounts on a shared IP$0
Optional static residential IPs$11–216/yr
Engineering — session store, ledger and persona config are already per-account~3–5 days, one time (~$1.2–2k)
LLMunchanged; scales with volume, not accounts

Multi-account is a small one-time engineering item, not a recurring infrastructure bill.

*What does stay expensive is account supply, not account operation.* Large subreddits
gate new accounts on age and karma. Growing one honestly takes 3–6 months; buying them breaks
Reddit's rules and they are banned in sweeps. No budget shortens that calendar, which is the
real reason the recommendation below still starts at one account.

The recommendation

Start with one account. Not as a limitation — as the correct sequencing. One real,
disclosed account posting genuinely useful replies tells you within two weeks whether any of
this works. If the replies land, scaling to 2–3 accounts with per-context proxies is a week
of work. If they do not land, you have learned that for the price of a fortnight instead of
a proxy contract and a fingerprinting problem.

Multi-account is in the architecture from day one — the session store, the ledger and the
persona config are all per-account — so nothing has to be rebuilt. It is simply not the
thing to turn on first, and per §4.4 it is cheap enough that the decision can wait until
there is evidence to base it on.

5. What redbot does differently, and why each one matters

1. Behaviour is data. Appilot compiles one bot per target per customer. A new behaviour
is a new binary, re-signed, re-downloaded, re-installed on every device. redbot interprets a
JSON workflow. New behaviour ships in minutes and is reviewable as a diff.

2. Selectors are a hot-swappable pack. ~60 Reddit element IDs are compiled into
Appilot's binary; every Reddit release can break them and every fix is a full rebuild-and-
redistribute cycle. redbot's live in a versioned data file with three fallback tiers, and
every resolution reports which tier won — so a selector degrading is visible days before
it fails.

3. Secrets cannot ship. Two live API keys — Anthropic and OpenRouter — are compiled into
the APK SGEN was given. An APK is a zip file. redbot reads credentials from the environment
only, and a CI check fails the build on a key-shaped string.

4. Disclosure is enforced, not requested. Appilot's prompt asks the model to mention
sgen.com "organically". redbot's linter refuses to queue any draft that mentions SGEN
without the disclosure line. A prompt is a request; models drift. A gate does not.

5. No manufactured authenticity. Appilot's prompts instruct the model toward "100% human
feel" — deliberate typos, fabricated war stories, invented personas. redbot's linter rejects
all three. The reply is good because it is genuinely useful and genuinely attributed, which
also happens to be what works on r/WordPress.

6. Every write is auditable. Logged before it is sent and after it lands, with content
and permalink. That log is the evidence trail if disclosure is ever questioned, and it is
the reason an unknown-outcome write is investigated by hand rather than blindly retried.

8. Definition of done

The MVP is accepted when all eight hold. Six need no Reddit account and no network.

  1. npm test green with the network disabled
  2. A JSON workflow drives a full read → score → qualify → draft cycle against the fixture site
  3. A draft mentioning SGEN without disclosure is rejected by the linter — with a test proving it
  4. A write exceeding the rate ledger is blocked — with a test proving it
  5. A workflow referencing upvote fails validation — with a test proving it
  6. The kill switch halts a running workflow mid-step — with a test proving it
  7. A live logged-out read-only run against reddit.com returns real, scored, qualified threads
  8. Zero secrets in the repository, asserted by a CI check

10. Recommendation

Approve P1–P4: **8 weeks, ~$20–40k, to a tested system proven against real Reddit data with
no account risk taken.** Decide on the pilot after P4, when there is something real to look
at rather than a proposal to imagine.

The honest summary: Appilot sold SGEN a working bot with six structural problems, two of
which — the compiled-in API keys and the undocumented voting — are things SGEN should act on
this week regardless of whether redbot is ever built. redbot is the same capability without
those problems, on the stack SGEN already runs, at roughly a fifth of the running cost, and
with the parts that create legal exposure enforced in code rather than requested in a prompt.
